Which flow?

How the shopper's selection gets back to you.

Should we automatically hold the seats for you?

Whether the seats are reserved as soon as the shopper finishes.

What happens to the seats

  1. The shopper selects their seats in the widget.
  2. Right after the shopper completes their selection, the seats are taken out of inventory for 15 minutes (booking.expirationMinutes) ON_HOLD
  3. You charge the shopper and confirm the booking (step 3c) CONFIRMED
  4. If it isn’t confirmed in time, the seats are released EXPIRED

Held 15 minutes by default (booking.expirationMinutes, 1–30). Exact deadline: booking.utcExpiresAt.

What happens to the seats

  1. The shopper selects their seats in the widget.
  2. The shopper completes their selection. Nothing is taken out of inventory yet, so others can still buy the seats.
  3. Your server holds the seats (step 3b) ON_HOLD
  4. You charge the shopper and confirm the booking (step 3c) CONFIRMED

Held 15 minutes by default (up to 30). Exact deadline: booking.utcExpiresAt.

Setup · before you start

Your token

Postman: Authentication

Every API call needs a token, sent as Authorization: Bearer <token>. We issue one for sandbox and one for production. Request them from tech@myticketpro.com. Keep it on your server and never put it in browser code.

Set it once. Every example on this page uses it.

export MTP_TOKEN="your-sandbox-token"
// mtp.js (Node 18+, no packages needed)
const MTP_API   = "https://api.sandbox.myticketpro.app/octo";
const MTP_TOKEN = process.env.MTP_TOKEN;

export async function mtp(method, path, body) {

    const response = await fetch(MTP_API + path, {
        method,
        headers: {
            "Authorization": `Bearer ${MTP_TOKEN}`,
            "Content-Type" : "application/json",
        },
        body: body ? JSON.stringify(body) : undefined,
    });

    const data = await response.json();

    if (!response.ok) {
        throw new Error(`${data.error}: ${data.errorMessage}`);
    }

    return data;
}
<?php
// mtp.php (PHP 8+, ext-curl)
const MTP_API = "https://api.sandbox.myticketpro.app/octo";

function mtp(string $method, string $path, ?array $body = null): array
{
    $curl = curl_init(MTP_API . $path);

    curl_setopt_array($curl, [
        CURLOPT_CUSTOMREQUEST  => $method,
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HTTPHEADER     => [
            "Authorization: Bearer " . getenv("MTP_TOKEN"),
            "Content-Type: application/json",
        ],
    ]);

    if ($body !== null) {
        curl_setopt($curl, CURLOPT_POSTFIELDS, json_encode($body));
    }

    $data   = json_decode(curl_exec($curl), true);
    $status = curl_getinfo($curl, CURLINFO_HTTP_CODE);

    if ($status >= 400) {
        throw new RuntimeException("{$data['error']}: {$data['errorMessage']}");
    }

    return $data;
}

def mtp(method, path, body=None):

    response = requests.request(

        MTP_API + path,

// MtpClient.cs (.NET 6+, no packages needed)
using System.Net.Http.Json;
using System.Text.Json.Nodes;

public class MtpClient
{
    private readonly HttpClient http = new()
    {
        BaseAddress = new Uri("https://api.sandbox.myticketpro.app/octo/"),
    };

    public MtpClient(string token)
    {
        http.DefaultRequestHeaders.Authorization = new("Bearer", token);
    }

    public async Task<JsonNode> Send(HttpMethod method, string path, object? body = null)
    {
        using var request = new HttpRequestMessage(method, path);

        if (body != null)
        {
            request.Content = JsonContent.Create(body);
        }

        using var response = await http.SendAsync(request);
        var data = JsonNode.Parse(await response.Content.ReadAsStringAsync())!;

        if (!response.IsSuccessStatusCode)
        {
            throw new HttpRequestException($"{data["error"]}: {data["errorMessage"]}");
        }

        return data;
    }
}

Step 1a · server

Find the productId

GET/octo/products

Postman: List Products

Each product in the response has an id, like "product-123". That is your productId. Look it up once and save it. It does not change. 

curl https://api.sandbox.myticketpro.app/octo/products \
     -H "Authorization: Bearer $MTP_TOKEN"

var productId = (string)products[0]!["id"]!; // pick yours by name, then save it

Step 1c · server

Create the widget

POST/octo/widgets

Postman: Create Widget

Save the uuid with your order. You need the url in step 2.

Parameter Required What to send
Authorization header Yes Bearer <token>. See "Before you start".
Content-Type header Yes application/json
productId Yes From step 1a.
optionId Yes Always the text "widget".
availabilityId Yes From step 1b.
returnUrl No null for this flow.
returnUrl Yes The page on your site that the shopper returns to. It must start with https://. We add ?widgetUuid= to it.
createBooking No Default true. Set by "Should we automatically hold the seats for you?" above.
booking.expirationMinutes No How long those seats are held after the shopper finishes. Default 15, max 30.
booking.uuid No Your own uuid for the booking. Default: the widget uuid.
booking.notes No Free text saved on the booking.
expirationMinutes No How long the widget link works. Default 1440 (24 hours), max 10080 (7 days).
unitItems No Pre-selected tickets, like [{"unitId": "price_type-adult"}], one entry per ticket. Leave it out to let the shopper choose.
unitItemsEditable No Default true. false locks the pre-selected tickets.
uuid No Your own uuid for the widget. Default: we create one.
currency No Only "USD".

Step 2 · browser

Embed it and listen

JSwindow.addEventListener("message")

This runs in your page, in the browser. Put the url from step 1c in both places.

  • change: fires on every selection change, including when the selection is cleared. It carries the full current selection and may repeat.
  • complete: fires once, when the shopper finishes. It has the same payload as change. Then go to step 3.
  • resize: {uuid, height}. The height is 800 while the shopper selects, and stays 800 after completion. If the widget opens already expired, canceled or completed, it is the height of that message.
  • The widget sends only the target height, not the steps in between. To animate the change, put transition: height 500ms ease-in-out on the iframe. Start it at height: 800px, with scrolling="no" and overflow: hidden so no scrollbar flashes while it resizes.
  • The payload is {uuid, unitItems, pricing}. unitItems has one entry per ticket. pricing is in cents and comes from the browser. Charge booking.pricing.retail.

HTML + JavaScript, in your page

<iframe id="octo-widget" src="{widget.url}" scrolling="no"
        style="width:100%; height:800px; border:0; overflow:hidden; transition:height 500ms ease-in-out;"></iframe>
<script>
    const widgetOrigin = new URL("{widget.url}").origin;
    const iframe       = document.getElementById("octo-widget");

    window.addEventListener("message", (event) => {
        if (event.origin !== widgetOrigin) return;

        const { type, version, payload } = event.data || {};
        if (version !== "1") return;

        if (type === "octo.widget.change")   updateSummary(payload);
        if (type === "octo.widget.complete") onWidgetComplete(payload.uuid);
        if (type === "octo.widget.resize")   iframe.style.height = payload.height + "px";
    });
</script>

Step 2 · browser

Send the shopper to the widget

JSwindow.location.href = widget.url

Open it as a full page, not in an iframe. When the shopper finishes, the widget sends them to returnUrl?widgetUuid={uuid}. Your existing query string is kept. Then go to step 3.

JavaScript, in your page

window.location.href = "{widget.url}";

Step 3a · server

Read the result

GET/octo/widgets/{uuid}

Postman: Get Widget

The widget is now COMPLETED and single use.

The booking is already held for booking.expirationMinutes (default 15, max 30) from completion. Go to 3c.

Nothing is held yet. Go to 3b.

     -H "Authorization: Bearer $MTP_TOKEN"
