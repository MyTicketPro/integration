Mint a widget uuid

A widget is one buyer's selection for one event, addressed by a uuid. This page mints one against using the partner session this browser already has, and links the result straight into the demos. It runs only under the dev server — it is not deployed anywhere.

1. Pick an event

Type at least two characters, or put an id straight into the field below.

    The catalogue is public and unscoped, so this search needs no session. It lists on-sale, active events only — which is the same rule the mint applies, so every row here is a row the mint will accept.

    2. Mint

    Filled by the search above, and editable either way. 256 is a clean test event on dev.

    Set it for redirect mode: the widget navigates itself there with ?widget_uuid={uuid} appended and posts no complete message. Blank means postMessage mode. The two are mutually exclusive and decided here, at mint time.

    The default. It holds a cart for the selection; unchecked, the widget only records what was picked.

    The call goes out with this browser's partner_access_token cookie. If you are not signed in to the partner app, sign in there and come back — or use an access token instead.

    Sent as Authorization: Bearer whenever this field is not empty, and the cookie is dropped for that call. Send one or the other, never both: the API answers 400 access token conflict between cookie and header. Nothing is stored — the token lives in this field and is gone on reload.

    Your widget

    A widget is single use. Once its selection is submitted, loading it again shows "This selection has already been submitted." Mint a fresh one per buyer, per attempt.
